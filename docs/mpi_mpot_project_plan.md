# Distributed MPOT Course Project Plan

This document records the current design decisions for adapting the MPOT
repository into a Parallel Computing / Parallel Programming course project.

The key goal is to build a CPU-based distributed MPI benchmark for physical
MacBooks. The goal is not to reproduce the original CUDA/GPU performance of the
NeurIPS MPOT paper.

## Main Design Choice

Use task-level parallelism with exploratory decomposition.

Each MPI process receives a subset of random seeds / candidate trajectory tasks.
Each process runs a local MPOT-style trajectory optimization on its assigned
tasks. Rank 0 gathers compact results from all ranks and chooses the global best
trajectory.

For a report-ready explanation of how the original MPOT optimizer works and
exactly where the MPI layer is added, read `docs/mpot_algorithm_overview.md`.
For the shorter mathematical algorithms to paste into the final report, read
`docs/mpot_parallel_algorithm_spec.md`.

```text
Rank 0:
  - Load experiment config.
  - Create deterministic seed/task list.
  - Distribute tasks by cyclic mapping.
  - Gather local best results and timings.
  - Select global best result.
  - Always write local CSV/JSON/PNG artifacts.
  - Optionally log summary metrics to W&B.

Rank 1..P-1:
  - Receive config and task list.
  - Run local MPOT-style optimization on CPU.
  - Return best trajectory, best cost, hostname, and timing data.
```

## Parallel Mapping

Use 1D cyclic mapping:

```text
task i -> rank (i mod P)
```

This is preferable to simple block mapping for the report because it gives a
clear load-balancing story when some seeds/tasks take longer than others.

## Correctness Requirement

The serial and MPI versions must use the same deterministic seed list.

Correctness is not defined as bit-for-bit reproduction of the original MPOT
paper. For this stochastic benchmark, correctness means:

- The serial baseline and MPI run cover the same task IDs and seeds.
- Each task is assigned to exactly one MPI rank.
- Rank 0 uses deterministic reduction when selecting the global best result.
- With the same config and seed list, MPI returns the same global best task/cost
  as serial within a small numerical tolerance.
- The saved best trajectory starts at the configured start state, reaches the
  goal, avoids hard obstacle collisions, stays inside workspace bounds, and has
  finite values.

Recommended tie-break:

```text
min(best_cost, then task_id, then seed)
```

## Report Mapping

Use these terms consistently in the report:

- Parallel level: task-level parallelism.
- Decomposition: exploratory decomposition over random seeds / candidate
  trajectory batches.
- Local compute: vectorized PyTorch operations inside each process.
- Mapping: 1D cyclic assignment.
- Communication topology: SPMD with rank 0 coordinator and logical star
  topology.
- Communication primitives: blocking `bcast`, `scatter`, `gather`.
- Granularity: coarse-grained tasks with large local compute and compact
  messages.
- Load balancing: compare per-rank compute and total times.
- Speedup: `S(P) = T(1) / T(P)`.
- Efficiency: `E(P) = S(P) / P`.

## Practical macOS Notes

- Default device must be CPU.
- Use `torch.set_num_threads(1)` inside each MPI rank to avoid oversubscribing
  CPU threads.
- Avoid CUDA-only code paths.
- Avoid heavyweight robotics visualization dependencies in the benchmark path.
- Prefer a simple 2D point robot with circular or grid obstacles.
- Keep visual outputs simple and local: static PNG plots are enough for the
